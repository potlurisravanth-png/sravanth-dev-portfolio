Secure File-Sharing on AWS

A file-sharing web app split so each service does one job, with only the access it needs.

Flask · EC2 · S3 · RDS (MySQL) · Lambda · SES · IAM

Code on GitHub

  1. Follow one upload.

    The file in the middle of the screen stays put while the system slides past it. Each stop does one job and holds only the access that job needs.

  2. Browser

    The upload

    A user sends a file through the app’s web form.

  3. EC2 · Flask

    The web app

    Python Flask on EC2, with Jinja2 templates, takes the request.

    Security group: who may reach it

  4. S3 + RDS

    S3 keeps the file

    The upload is stored as an object in S3.

    RDS keeps the record

    File metadata and users live in RDS (MySQL).

  5. Lambda

    Decoupled

    An S3 event, or an API call, triggers a function, so notifications run apart from the web app.

  6. SES

    The notification

    The function sends the email through SES.

  7. Behind every hop: IAM roles and security groups, set for least-privilege access.

Least privilege, by design.

Compute, storage, data and notifications are separate managed services, and IAM roles and security groups decide what each piece may touch.

On the list, not built

Presigned URLs for direct downloads from S3 are optional, future work, and Auto Scaling for the EC2 tier is a design option, not a running feature.

  • FrontendHTML and CSS through Jinja2 templates
  • BackendPython Flask on EC2
  • StorageS3
  • DatabaseRDS (MySQL), through PyMySQL
  • Async tasksLambda and SES
  • AWS accessBoto3
  • ConfigurationEnvironment variables for the database and the bucket

Every piece holds only the keys it needs.

Built on AWS during the M.S. in Data Science at UAB. The code and setup steps are on GitHub.
