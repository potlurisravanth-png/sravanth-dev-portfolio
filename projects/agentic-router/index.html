Agentic Router

One request, itemised

  1. 1RouteA learned route map, built from thousands of graded answers, picks the cheapest model expected to pass this kind of question.
  2. 2CheckThe answer is checked before it is trusted.
  3. 3Climb, or flagIf the check fails, a stronger model from the low-cost pool answers. Past the top of the pool, the request is flagged for a frontier model.
  4. 4ReceiptThe model, the reason and the real cost.

Inside Claude Code

In agent mode, Claude hands mechanical repository work to a cheap worker through MCP. The worker edits a copy and runs the tests in a sealed container. Claude reads the change and accepts it, or sends it back with a comment.

  1. Claudeplans the task and reviews the result
  2. Cheap workerreceives the task over MCP and edits a copy
  3. Sealed containerruns the hidden tests
  4. Claude againaccepts the change, or sends it back to the same worker with a comment
  1. Haikulooks around
  2. Sonnetmakes the change
  3. Opusreviews it

A brain that learns from reviews

Every accepted or rejected change teaches the router which worker suits which kind of task, weighing cost, speed and first-pass acceptance. A hook picks the right Claude model for each step, inside your own Claude subscription.

A live dashboard that stays local

A local page shows which model did each step, why it was chosen, and what the brain has learned, updating as new results arrive. It reads only your own files and never leaves your machine.

Every experiment is pre-registered.

The pass mark is written down before the run, and the result is reported whether it passes or fails. New behaviour ships switched off until the evidence is in.

Status: a private, proprietary SDK in active development. The public page is an overview by design, and a methodology paper on the equal-budget verification protocol and the verifier-bounded frontier is in preparation.
