Agentic Router

A cross-provider LLM router that picks the cheapest model that still passes — and proves it.

Every routing decision is auditable: each request comes back with a receipt, and the cost on that receipt is reconciled against the provider's own billing.

The Challenge

LLM inference cost is dominated by sending easy prompts to expensive models. Routing fixes that — but most routers are black boxes: you cannot see why a model was picked, and you cannot trust that the cost they report is real.

  • Opaque decisions: no record of which model handled a request, or why.
  • An untrustworthy meter: in-process cost trackers can badly undercount real spend on reasoning tokens — this project's own tracker once recorded $0.14 against $2.16 actually billed. If you cannot trust the meter, you cannot trust the router.
  • False economy: a cheap model that is good enough on average fails quietly on the prompts that are actually hard.

The Approach

Agentic Router treats honesty as a first-class feature: the routing decision, the models used and the real cost are on the record for every request.

Per-route receipts

Every call returns the tier chosen, the model or models that ran, and the real cost.

Cost reconciliation

In-process accounting is checked against the provider's billing API. A divergence beyond a tight threshold fails loudly instead of silently undercounting.

Verifier-bounded routing

A cheap model's answer is checked before it is trusted. If it fails, the router climbs to a stronger model in its low-cost pool, and a request beyond that pool is flagged for a frontier model on top, such as Claude Code, rather than pretending cheap was good enough.

Drop-in endpoint

An OpenAI-compatible endpoint, so the router sits in front of existing tools and editors without code changes.

How a Request Flows

The router starts cheap and pays for a stronger model only when the cheap answer does not hold up.

  1. 1

    Route

    Send the prompt to the cheapest model expected to pass.

  2. 2

    Verify

    Check the answer before trusting the cheap result.

  3. 3

    Escalate if it fails

    Step up to a stronger model in the low-cost pool instead of guessing; past the top, flag it for a frontier model. A pass skips straight to the receipt.

  4. 4

    Receipt

    Return the tier, the models and the real cost, reconciled against provider billing.

Agent Mode (Experimental)

The newest work takes routing from single prompts to whole tasks. Agent mode runs as an MCP server that Claude Code connects to: Claude hands a repository task to a cheaper worker model, the worker makes the change on a copy, and Claude reviews it — accepting the change or sending a comment back to the same worker.

It is measured the same way as everything else here: against a pre-registered cost-and-quality gate, with the misses reported alongside the wins. On eight real tasks in this repository, handing the work to cheap workers first cost 25% less than Claude Opus at low effort, with every hidden test still passing. A router hook that picks Claude's own model for each hand-off — Haiku to look around, Sonnet to make the change, Opus to review — cost 45% less.

The worker for each task is chosen by a brain that learns from review verdicts, weighing each model's cost, speed and first-pass acceptance, and a who-did-what view shows which model did each step, why it was chosen, and what it cost.

How It Is Evaluated

Pre-registered, negative results included

  • Experiments are pre-registered: the gate is written down before the run, on public benchmarks and on real tasks.
  • Results are reported whether they pass or fail, and new behavior ships switched off until the evidence is in.
  • On 1,095 public benchmark questions (MMLU-Pro, GPQA, MATH-500, HumanEval+, Bamboogle), the learned route map matched the best single model's accuracy at 54–68% of its cost.
  • On genuinely hard tasks, a frontier model holds an accuracy edge that cheaper models cannot close even with an equal verification budget — so the router flags those requests for a frontier model instead of guessing.
  • Every live run is reconciled against the provider's own billing; the latest runs matched to within 0.5%.

A methodology paper on the equal-budget verification protocol and the verifier-bounded frontier is in preparation.
